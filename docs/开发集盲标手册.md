# ACRIN 6668 开发集独立盲标手册

版本 `acrin-review-dev-v1`，2026-11-25。供两位独立标注人和一位仲裁人校准口径。每位标注人收到同一份开发集任务文件。本轮有 9 个病例族、122 个截点，每位标注人各自完成 122 条判断。

## 每个截点回答什么

只根据本条任务的可见事件，判断资料能否交给相应专科做科研复核。写明已经查到的事实、回答本次资料问题仍缺的记录，以及需要保留的矛盾。标注范围限于资料审阅，不给患者制定诊疗方案。

| 流程标签 | 采用条件 |
| --- | --- |
| `READY_FOR_REVIEW` | 已有记录足以让所选专科复核本次资料问题。说明支持复核的事实及其适用范围。 |
| `NEED_MORE_INFORMATION` | 能指出一项或多项具体缺件，补到这些记录后即可继续复核。写明需要哪份记录。 |
| `DEFER_DECISION` | 材料之间存在影响判断且暂时无法解释的矛盾，或资料的对应关系、时点或来源无法查证。记录需要谁核对哪件事。 |

资料缺失且有矛盾时，判断矛盾是否使已有事实也无法使用。若会，保留双方证据并说明暂缓原因。若影响仅限缺少某项记录，列出该项缺件。把确实需要参与复核的专科加入 `required_agents`，可选肿瘤内科（`oncology`）、影像科（`radiology`）、胸外科（`surgery`）和病理科（`pathology`）。写明每一科需要解决的问题。

## 如何读材料和留依据

1. 按任务文件顺序一次阅读一条。核对 `scenario_id`、最后一条事件和 `input_sha256`。同一病例后面的任务可能增加新资料，提交当前判断后再读下一条。日期是公开数据的相对时间锚点。同一天的事件编号只确定回放顺序。
2. 在 `evidence_ids` 中填入支持判断的“事件编号:事实键”。可以引用两条相互冲突的记录。记录 PET 已完成、存在 PET 判读、具备完整报告是三个不同的事实；随访评估时间和研究中心收到表格的时间也须区分。
3. `missing_fields` 每行一个缺项。两位标注人在开发集校准时商定同义词与字段键，保留口径版本。正式初标时各自独立判断缺项是否适用。`expected_conflicts` 记录相互矛盾的事实；使用网页时可在理由框同时写下两条证据编号和冲突内容。`rationale` 写一至三句，说明哪些资料支持结论、哪些问题仍待核验。
4. 每人使用自己的标注编号。初标期间只查看分配的材料和本人的记录。可先用独立的旧演示样例熟悉表单，记录开发集口径的修订日期；若口径改变，标明受影响截点并保存原稿。

## 提交与仲裁

组织者保管冻结清单及评分表，只将 `dev_tasks.jsonl` 和本手册交给两位标注人。打开“实验与盲标 → 多人盲标 → 独立盲标录入”，在“载入独立盲标任务（JSONL）”选择任务文件，确认页面显示“已分配 122 个截点”，然后启用本人的标注编号。队列、分页和“下一待标截点”均限于文件内的任务，可以连续保存。工作台使用研究库中的材料，逐条核对任务文件指纹才开放表单。遇到缺失版本或指纹不匹配时，由组织者核对导入批次。初标完成后再由仲裁人在全库视图复核双方意见。[接口与字段](API与事件契约.md#多人盲标仲裁与独立时间边界审计)

仲裁人收到两份初标后，先按场景编号和材料指纹核对双人覆盖数，再查看分歧。逐条保存共识、引用和理由，保留两份原始初标。对关键证据和矛盾的文字差异也需人工复核。汇报共同标注的截点数、原始一致率、固定两位标注人的三分类 Cohen’s κ，以及必要专科集合的 Jaccard。κ 无法定义时保留原始列联表，并写明原因。
