# V0.3 协作实施契约

本轮实现《最终方案》中的本地可演示闭环；暂停论文。旧 CLI、/api/v1、旧报告保持兼容。新代码位于 `src/mdt_demo/research/`，新 API 为 `/api/v2`。新增数据均为手工合成研究场景，不宣称来自 Synthea/TCIA。

## 数据（JSON / Pydantic 同名字段）

- ResearchCase: `case_id, title, disease, case_kind="synthetic", version:int, patient:{age,sex}, current_question, timeline:ClinicalEvent[], provenance:Provenance[]`。
- ClinicalEvent: `event_id, occurred_at`（YYYY-MM-DD）, `event_type, title, facts:dict[str,scalar|null], source, source_record_id:null|string, synthetic_extension:bool, confidence, introduced_in_version:int`。事件追加不覆盖历史；日期+ID排序；历史运行冻结病例版本与触发事件之前的上下文。
- Event types: diagnosis, imaging, pathology, molecular_test, procedure, treatment, medication, toxicity, follow_up, progression, recurrence, observation。
- Provenance: `source_name, source_url:null|string, dataset_version, license, synthetic:bool`。
- append 请求: `{expected_version:int, event:{occurred_at,event_type,title,facts}}`；服务器生成事件ID、来源 `research_scenario_generator`、synthetic 标记与新版本。过期版本返回409。
- RunRequest: `{case_id, case_version:int, trigger_event_id, mode:"mock"|"llm", mock_scenario:"standard"|"partial_failure"|"persistent_disagreement"|"invalid_evidence", routing_mode:"event"|"fixed"}`。
- 角色 registry: oncology, radiology, surgery, pathology。
- Routing: `{strategy_version, trigger_event_id, selected_agents:string[], skipped_agents:string[], reasons:{agent_id,rule_id,description}[]}`。
- EvidenceRef: `{evidence_id,event_id,fact_key,value,source_name,source_record_id,dataset_version,synthetic,quote_or_fact}`，**由后端**从冻结上下文事实生成，evidence_id 为 `event_id:fact_key`。
- 模型原始输出 AgentOutput: `{agent_id,decision,summary,evidence_ids:string[],claims:{fact_key,value,evidence_id}[],missing_information:string[],confidence}`。decision 使用现有三个资料审阅标签；confidence low/medium/high。
- 通过结构与引用校验后生成 Opinion: 上述字段（可保留evidence_ids）加 `opinion_id,evidence_refs:EvidenceRef[],model_info:{provider,model,prompt_version,attempts,prompt_tokens:null|int,completion_tokens:null|int}`。模型不能提供来源元数据。
- Conflict: `{conflict_id,dimension,agent_ids:string[],description,evidence_ids:string[]}`。
- Safety: `{decision,status:"passed"|"needs_information"|"blocked",checks:{code,status:"passed"|"warning"|"blocked",message,evidence_ids:string[]}[],missing_information:string[],warnings:string[]}`。
- Metrics: `{agent_calls,llm_calls,tool_calls,retry_count,prompt_tokens:null|int,completion_tokens:null|int,elapsed_ms}`；Mock token 使用null。

## 引擎模块（domain agent）

`research/schemas.py`: 上述模型，RunRequest 与 ResearchCase 至少导出。
`research/seeds.py`: `seed_cases() -> list[ResearchCase]`，3个带多事件的肺癌合成病例：逐步补齐信息、缺失资料、证据冲突。数据source为本地手工合成，不冒充外部数据。
`research/engine.py`:

```python
def route_case(case: ResearchCase, trigger_event_id: str, routing_mode: str = "event") -> dict: ...
def execute(case: ResearchCase, request: RunRequest, run_id: str,
            emit, cancelled, llm=None) -> dict: ...
```

emit 调用为 `emit(type, stage, payload, agent_id=None)`。cancelled 无参返回 bool；取消抛出 `WorkflowCancelled`。阶段 INITIALIZING, ROUTING, AGENTS_RUNNING, CONFLICT_CHECK, DISCUSSION, SAFETY_CHECK, REPORTING。引擎不写文件、不持有数据库。最多单轮针对冲突参与者的讨论，每角色初始调用一次；无医学共识或模型准确率宣传。

LLM callable 入参context字典: `run_id,case_id,case_version,agent_id,phase,current_question,trigger_event,events,evidence_registry,current_facts,required_fields,missing_information,prior_opinion,peer_opinions,conflicts`。返回 AgentOutput 字典加服务端 `model_info`。callable可有 `.metrics`，含真实LLM调用/重试/token统计，包括失败调用。异常只暴露稳定的 `.code`，不记录异常原文。

主要emit约定：`workflow.stage_changed` payload `{stage}`；`routing.completed` payload Routing；`agent.started` payload `{phase}`；`agent.completed` payload `{phase,opinion}`；`agent.failed` payload `{phase,error_code}`；`conflict.detected` payload `{conflicts}`；`discussion.started/completed`；`safety.completed` payload Safety；`tool.completed` payload `{tool, evidence_ids}`。metrics放最终report；进度为真实completed_nodes/running_nodes/pending_nodes。

Report: `run_id,case_id,case_version,trigger_event_id,mode,mock_scenario,routing_mode,case_snapshot:ResearchCase,routing:Routing,evidence_registry:EvidenceRef[],initial_opinions:Opinion[],final_opinions:Opinion[],conflicts:Conflict[],unresolved_conflicts:Conflict[],discussion_records:{agent_id,before,after:null|Opinion,changed}[],discussion_rounds:int,safety:Safety,final_decision,status:"completed"|"incomplete"|"failed",metrics:Metrics,disclaimer`。

信息充分性来自显式事实与当前事件类别；false/null/缺失表示待补。已有关键缺失不能READY；非法证据、失败角色、未解决分歧则DEFER。检查以selected_agents为分母。引用正确只证明输入一致，不证明医学正确；界面/报告保留这一边界。

## 服务（backend agent）

`research/store.py` SQLite append-only events + versioned cases + run snapshots/audit/report；`research/service.py` 有界2线程/最多4运行，边界取消，服务重启将活动任务记录为中断失败；`research/api.py` APIRouter。

GET `/cases`, `/cases/{id}?version=`, POST `/cases/{id}/events`, GET `/cases/{id}/routing?trigger_event_id=&version=&routing_mode=`。
POST `/runs`, GET `/runs`, GET `/runs/{id}`, POST `/runs/{id}/cancel`, POST `/runs/{id}/rerun`, GET `/runs/{id}/report`, GET `/runs/{id}/report/download`, GET `/runs/{id}/audit?after_seq=0&limit=500`, GET `/runs/{id}/audit/download`。
GET `/runs/{id}/events` 为SSE，`id:seq` + `data:JSON`（不设置自定义event名，前端onmessage）；支持Last-Event-ID/after_seq；心跳comment；终态关闭。
所有普通REST响应 `{data:...}`，错误 `{error:{code,message}}`；审计页data=`{events,next_seq}`。允许原有request_id等附加字段。

RunSnapshot: `run_id,case_id,case_version,trigger_event_id,mode,mock_scenario,routing_mode,status,stage,created_at,updated_at,last_seq,routing:null|Routing,agents:{agent_id,status:"idle"|"queued"|"running"|"completed"|"failed"|"skipped",opinion:null|Opinion,previous_opinion:null|Opinion,error:null|string}[],conflicts:Conflict[],safety:null|Safety,report_ready,cancel_requested,completed_nodes:string[],running_nodes:string[],pending_nodes:string[],metrics:Metrics,error:null|string`。

AuditEvent: `{event_id,run_id,seq,timestamp,type,stage,agent_id:null|string,payload:dict}`。

服务集成由backend agent修改旧api.py生命周期：`app.state.research`；安全源检查覆盖所有写方法，增加PUT/DELETE的CORS。旧v1不变。测试store使用tmp独立DB。

## 模型设置（root）

`research/provider.py` 内存SettingsService：`status()->dict`, `configure(body)->dict`, `clear()->dict`, `test()->dict`, `make_generator()->callable`。provider为openai-compatible，默认base_url=https://api.openai.com/v1，model默认为空由用户配置。配置请求 `{provider,base_url,model,api_key,timeout_seconds,temperature,max_output_tokens}`。secret永不回显、写DB或日志。仅服务端可发外部HTTP；https目标且拒绝凭据/查询串/内网目标；不跟随重定向。单次最多重试一次；严格JSON输出与验证；使用httpx注入transport测试，不调用真实付费API。

`research/provider_api.py` 提供router( `/api/v2/settings/llm` GET/PUT/DELETE；POST `/test`)；从app.state.research.settings取得SettingsService。后端service构造该对象，LLM运行创建时冻结generator配置；尚未配置拒绝启动，不降级Mock。

## 前端（frontend agent）

新增 `frontend/src/research/` 独立Zod契约/api/SSE/pages；可复用旧Icon和样式。修改App.tsx主入口 `/` 为新病例库，旧home移到 `/legacy`，旧v1路由仍保留。新页面 `/research/cases/:id`, `/research/runs`, `/research/runs/:id`, `/research/runs/:id/report`, `/settings/models`。导航以新工作台/运行记录/模型设置/研究路线为主；保留基础Demo入口。
追加事件先用受控模板+可编辑日期标题与facts JSON（校验），展示明确合成来源。调度预览与新版本、不同触发事件可运行；固定全员与事件调度可比较真实角色/调用数。动态4角色卡支持skipped。证据从Report.case_snapshot/evidence_registry获取，禁止读最新病例冒充旧运行证据。模型保存后清空密码输入，不写storage，不回显key。
SSE按连续seq确认，缺口缓冲+REST补拉；终态关闭；快照last_seq单调合并；重连计时从断线开始。前端不能伪造百分比、Token或结论。原生事件与snapshot分别使用，首版可依快照轮询更新角色状态、SSE更新审计。
